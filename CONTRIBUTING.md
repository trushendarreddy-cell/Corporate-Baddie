# Contributing

## Before You Commit

- Keep the change focused.
- Preserve existing public component contracts unless the change requires an update.
- Do not add secrets, API keys, private datasets, or generated dependency folders.
- Do not present mock data as a real investigation result.
- Add or update documentation when behavior changes.

## Commit Style

Use small commits with clear messages. Good examples:

- `docs: add project development guide`
- `feat: calculate decision confidence from run evidence`
- `fix: block recommendations when required evidence is missing`

## Pull Requests

Describe the behavior changed, the evidence or data path affected, and the validation commands that passed. Include known limitations when a feature still uses demo data.
